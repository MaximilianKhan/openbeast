# Eval suite changelog

## v4.1 (2026-10) — validator and harness corrections (CURRENT)

Same 137 base tasks / 291 effective units as v4. **v4.1 numbers are NOT
comparable to v4**: two validators, 132 fixtures and the eval harness changed.
The eval era moves `b5596c660b5ab819` → `c21335b8e331f734`
(`scripts/eval-era.sh`), so no v4 cache entry is reachable from a v4.1 run.
The nine v4 board rows are kept, ranked among themselves in their own
section; a v4.1 run never replaces a model's v4 row. Source: the 2026-10-09
measurement-integrity review (findings F1, F2, F4, F5, F6, F10, F12).

Task specs (134 of 291 unit hashes change):

- **`23_sql_injection`** — the validator rejected the canonical parameterised
  fix when the LIKE pattern was built inside the `execute()` call and accepted
  SQL concatenated outside it. All 21 live v4 rows fail the task on that
  assertion (−0.68 SCORE per board row). Now: only the SQL argument is judged,
  followed to its assignments; `/search` and `/user` get injection tests; a
  quote in a legitimate value must work. 13 of 13 model solutions replayed
  from the agent logs pass.
- **`21_race_condition`** — passed with no synchronisation (20/20 with the
  yield deleted). The validator now forces a thread switch after every
  bytecode instruction in the solution. Unsynchronised variants fail 20/20,
  locks pass 20/20, in under 1 s.
- **132 variant units (22 base tasks × 6 languages)** — `expected.txt` is no
  longer written at setup, and validation runs on the sample plus hidden
  cases installed after the agent exits. Generated by
  `scripts/hide_expected.py` from the Python references; the literal-print
  cheat is rejected on 22 of 22 Python variants and all 185 reference
  solutions still pass.

Harness (`agents/runner.py`, `agents/tools.py`; eval mode only):

- A model request is bounded by the unit's remaining wall budget and never
  re-sent (was: a fixed 600 s and one silent retry, unscaled by `--jobs`). A
  timeout is counted as `request_timeouts`, a model verdict, not an API error.
- A running `TOKENS:` line per turn, so a wall-timeout row records the tokens
  of its completed turns instead of 0.
- The path guard's refusal reaches the model; its path list comes from the
  task text; it gives way after two refusals.
- `fetch` and `web_search` are not offered to an eval unit.

Scoring: `v4.1` is a suite of its own (`SUITE_EXPECTED_UNITS`, the board's
per-suite sections, and a dedup key that includes the suite from v4.1 on).

**v5-fast is stale.** The pin was built from v4 runs and is marked
`repin_required`, not corrected: `23_sql_injection` is still listed
`assumed_failed`. Regenerate it from full v4.1 runs before trusting an
imputed score.

Not closed: `bash` still has network access; validators, hidden cases and
reference solutions are readable from `evals/tasks/` and `evals/refs/` (one
agent log of 3,144 shows a unit copying a reference solution); the remaining
53 variant units and 106 single-language tasks were not re-audited.

## v5-fast overlay (2026-09-08) — pinned fast subset, imputation-scored

NOT a new suite version — v4 stays current and frozen; v5-fast is a pinned
SELECTION of it (`evals/suites/v5-fast.json`): the 86 units that
discriminate between reference models + 20 all-pass tripwires. Runs via
`--suite v5-fast`, scores by imputing the 185 saturated units, which
reproduces full-291 capability exactly for in-family models (identity
verified per reference run by `make_fast_suite.py`; raw-subset ranking
measured at τ = +0.810 and rejected). Fast runs never enter the
leaderboard and share cache keys with full runs. ~0.85 h with `--jobs 4`
vs ~5.6 h full.

## v4 (2026-07-08) — the hardened suite

137 base tasks / 291 effective units across all 12 topic categories.

A full adversarial re-review of v3.5 (see `docs/archive/EVAL_REVIEW_2026-07-07.md`)
found 117 of 159 tasks flagged — inflators (empty submissions / naive
algorithms / dead perf gates passing), deflators (correct code failing on
broken fixtures or comment-tripping lints), and unverifiable properties.
v4 is the rebuild (plan: `docs/archive/EVAL_V4_PLAN.md`):

- **Pruned 25** overlapping / unverifiable tasks (159 → 134).
- **Added 3 DSP tasks** (160 FIR, 161 Goertzel, 162 biquad IIR) so Signal
  Processing is a real category (1 → 4 tasks). Net: 137 tasks.
- **Every surviving flagged task hardened + verified BOTH ways**
  (reference passes; the documented cheat is empirically rejected) under
  9 systemic rules: pre_validate on all fixture tasks, comment/string-
  proof anchored lints, no readable answers, perf/memory gates measured
  to ≥10x, printf fixtures, self-contained variant texts, promise↔assert
  parity, durable 6-language refs, ≥5x timing margins.

v4 numbers are NOT comparable to v3.5. The v3.5 leaderboard is retained as
the "before" for the launch narrative and will be archived on a later
formal-display pass.
