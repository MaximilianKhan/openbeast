## Model Serving
- llama.cpp with CUDA (Blackwell SM 120), full GPU offload
- Up to 6 parallel request slots with unified KV cache and continuous batching. **The shipped default does not use them:** Qwen3.8 27B Uncensored MTP pins `-np 1`, because llama.cpp's MTP speculative decoding does not support more than one slot — concurrent requests serialize. That is the deliberate trade for 2.0× decode (140 tok/s vs 69.9) at the full native 262K context. Switch to `serve-qwen38-27b-uncensored-q5.sh` — the same weight file, MTP simply not activated — to get the 6 slots back at half the tokens/s.
- 23 pre-configured models (one `scripts/serve-*.sh` each, all VRAM/context-measured on the 5090), capability-ranked on the hardened v4 eval suite — default **Qwen3.8 27B Uncensored MTP Q5_K_M** (262K context); full lineup in [MODELS.md](MODELS.md), scores in the [leaderboard](RESULTS.md). `scripts/fetch-weight.sh <file>` downloads any registry weight by name, staged and sha256-verified before it lands (a mismatch deletes the file rather than leaving it to be served)
- Context lengths tuned to measured VRAM ceilings (192K–512K) on a 32GB card; MTP variants additionally pin `-np 1` per upstream constraint
- **Reasoning on by default.** The shipped Qwen models are "thinking" models — full chain-of-thought is on out of the box for maximum answer quality. It's a stateless *per-request* toggle (`chat_template_kwargs: {enable_thinking: false}`), so automated sub-calls (e.g. a JSON classification or routing step) can opt out for speed and clean output without touching your deployment or any other request. A global `REASONING` / `REASONING_BUDGET` (in `openbeast.conf`) caps or disables thinking per deployment — the over-reasoning "MAX" tunes ship with a sane `--reasoning-budget` default.
- **Fast boot** (opt-in, `FAST_BOOT`): serve the tiny Qwen3-0.6B bridge on :8080 for instant chat, then hot-swap to the configured model once the stack is up and its weights are warmed.
- **Model load-failure rollback** (on by default, `MODEL_ROLLBACK`): if a model fails to load (OOM, missing/corrupt weight), revert to the last model that loaded healthy rather than leaving the stack down.
- **beast-assist** (opt-in, `BEAST_ASSIST=1`): compiler feedback pushed into the agent loop — after every `write_file`/`edit_file`, the language's checker (zig full-Sema, rustc, go vet, gcc/g++, py_compile, shellcheck) runs and its diagnostics land in the tool result, so the model learns *at write time* that its stale-stdlib call or syntax slip won't compile, instead of discovering it at the end (or never). Measured across two A/B replicates (2026-09-09/10, docs/LANG_AWARENESS_PLAN.md): every assist-ON cell passed more tasks than its OFF twin, completion tokens dropped ~2–4%, and no regression appeared on any non-target language — but the capability effect is small (≈+2-5 net tasks/run on the targeted language, inside a measured ±5-14 run-to-run churn floor; champion arm flat-null across two replicates), so the default stays OFF until the pre-committed next arms (Tier-3 awareness packs, the fixed checker era, a low-churn eval mode) can move it — full honest numbers in docs/LANG_AWARENESS_PLAN.md's results addendum. Per-write latency is recorded when enabled (p50/p95/p99 in run provenance). Missing toolchains no-op silently; eval rows produced with it carry their own cache era and an assist-aware provenance stamp.
- **Language awareness packs** (opt-in, `BEAST_PACKS=1` / eval `--packs`; Tier 3 of docs/LANG_AWARENESS_PLAN.md): a ≤2,000-token, version-pinned digest of the *installed* toolchain's current API injected into the agent's system prompt for tasks in that language — today only zig 0.16 (`agents/packs/zig-0.16.md`: a machine-verified old→new idiom map for the ArrayList / `std.Io` / removed-helper failure classes, plus a stdlib signature digest regenerated deterministically by `agents/packs/gen_zig_pack.py`). Other languages get nothing — their requests are byte-identical. Eval rows carry a task-scoped `pack1-<sha8>` cache era and `harness.packs` provenance, and the harness aborts if the pack drifts from the installed compiler. Effect is unmeasured until the pre-registered zig-only mini-A/B (`scratch/tier3_zig_ab.sh`) runs, so the default stays OFF. The zig verdict is post-processed (diag2, 2026-09-11): reference-trace noise is stripped (−57% payload on the fixtures) while declared-here signature notes are kept, unknown-member errors get a `did you mean` line sourced from the installed stdlib, a 5-row compile-verified fix-hint table fires on the ArrayList-arity / std.Io migration idioms, and the footer counts errors with an anchored pattern (`12 errors (3 shown)`).

## Tool Suite (18 tools, two surfaces)
- File operations: `read_file`, `write_file`, `edit_file`, `list_files`
- Code search: `grep` (regex), `list_files` (glob)
- Shell: `bash` with timeout and output capture
- Web: `fetch` (URL → readable text, SSRF-guarded), `web_search` (via local SearXNG)
- Agent management: `start_agent`, `check_agent`, `tail_agent`, `list_agents`, `stop_agent`
- Skills (curated expertise packages): `skill` (one tool: index + load, rescans on every call), `start_skill_agent`
- Artifacts: `publish_artifact`, `list_artifacts` — a self-contained HTML file in, a durable tailnet URL out (see **beast-artifact** below). MCP/WebUI surface only; deliberately **not** in the autonomous runner's 10-tool registry, so its tool-selection pressure is unchanged
- Language reference: `language_reference(language, topic, error)` — beast-lang's pull surface. Returns only what the toolchain *installed on this rig* confirmed (VERIFIED claims, GENERATED introspection facts, labelled): the cards for a compile error, the claims matching a topic, or the language's pack; a miss says "no verified reference" rather than padding. MCP/WebUI surface only, admin profile only, and — like the artifact tools — **not** in the runner's registry (local models do not call optional tools; for them the delivery is push + escalate, `docs/BEAST_LANG_PLAN.md` §2.1)
- **Identity-aware serving** (`agents/openapi_tools.py`, the WebUI surface): each WebUI account's files shard into `~/openbeast-files/users/<id>/` with a per-shard `.manifest.jsonl` write index (`FILES_SHARDING=user|chat|off`); per-profile RBAC keys checked on every call; per-call **audit trail** (`.run/tool-audit.jsonl` — who ran which tool when, argument digests only, never contents)
- MCP surface (`agents/mcp_server.py`, stdio) for OpenCode and any MCP client — same 18 functions, imported by the identity server so the surfaces can't drift
- **Harness agentics** (2026-09-11, from the tools SOTA review): the autonomous runner gets two loop-only tools (`task_done`, `update_plan` — a Codex-style step ladder re-injected every turn as external memory) and **context-window management** (on the server's context-overflow error, or proactively past ~70% of `--context-budget`, the oldest tool results are stubbed to one line instead of retrying an identical oversized payload; counted per task as `compactions`). `edit_file` **teaches on failure** — a whitespace-normalized near-match search quotes the file's actual text with line numbers and names what differed (indentation, tabs vs spaces, pasted `N<TAB>`/`N:` line-number prefixes), routes to `write_file` after two consecutive failed edits on a file (SWE-Edit fallback routing) — and echoes a numbered **post-edit window** on success so no confirming `read_file` is needed. Tool schemas now state the facts local models act on: `bash` merged stderr / fresh shell per call / head+tail cap / background-process kill; `fetch` loopback-LAN-tailnet block; `read_file` **1-based** `offset` (matches `grep -n` and the numbers it prints); `web_search` `SEARXNG_URL` truth plus `pageno`/`time_range`.
- Private workspace: created `0700` by `start.sh`; configurable via `FILES_DIR` in `openbeast.conf` — persistent and private, never world-readable `/tmp`

## beast-lang (the offline language library)
A local model's knowledge of a language freezes at its training cutoff; the compiler on the rig does not. beast-lang (`agents/lang/`, [`BEAST_LANG_PLAN.md`](BEAST_LANG_PLAN.md) §10 for status) makes the **installed toolchain the ground truth**. It is a library, not a service: nothing listens on a port or runs at start, every entry point is a no-raise facade, and all of it is silent under `OPENBEAST_EVAL`.
- **L0 — the corpus** (`scripts/lang-library.sh acquire|check|list|verify|pack|where`): each language's reference docs fetched for offline use, resolved through a version index or release API at acquisition time (never a hardcoded artifact URL — two of ten assumed from memory were already 404), each artifact with a provenance manifest (source, sha256, license, fetch date, toolchain version described). Lives **outside** git (`OPENBEAST_LANG_DIR`, default `../openbeast-lang-library`) because cppreference is CC-BY-SA and ISO drafts are not redistributable; the repo ships the acquirer. Honours `OFFLINE`
- **L1 — introspection** (`scripts/lang-introspect.sh probe|render|write|check|list`, `agents/lang/introspect.py`): six mechanical probes, none of which executes a snippet — `g++`/`clang++ -dM -E` diffed across `-std=` levels (which feature macro appears at which level is *observed*, not recalled), the same for C, `zig env` → the real top-level `std` names (`std.Io` vs `std.io` is the suite's most expensive trap), Python's `sys.stdlib_module_names`, `go list std`, and which editions the installed `rustc` accepts. A full probe costs ~0.2 s, so the pack path asks the toolchain live on every call — there is no stale artifact on the serving path (`agents/lang/generated/` is gitignored per-rig state; `check` only answers "was this file edited?"). Eligibility for a pack is *claims ∪ probes*, so a language with an installed toolchain and no hand-written claims is still served: **six languages today** (zig, C, C++, Python, Rust, Go)
- **The verifier** (`agents/lang/verify.py`, `lang-library.sh verify`): every migration claim in `agents/lang/claims/` ships an OLD fixture that must **fail** and a NEW one that must **compile** on *this* rig, or it is not served. Three of the first ten claims were wrong; it caught all three
- **Awareness packs** (`agents/lang/packs.py`, `LANG_PACKS=auto|<list>|off`): a budgeted, version-pinned digest of VERIFIED claim summaries plus GENERATED toolchain facts, labelled by tier (generated lines are dropped first under budget), injected only for the language a task is in and only when the pack's stamped toolchain version matches the installed one — a pack for zig 0.15 handed to an agent compiling against 0.16 is wrong with authority
- **Escalation** (`agents/lang/escalate.py`): a compile error selects the card that fixes it. The matching index is generated, not hand-written — the OLD fixtures are compiled to harvest the real diagnostics — and it refuses to speak on no match, no index, a claim with no one-line summary, or an index stamped by a different toolchain than the installed one. Delivery into beast-assist's checker verdict (`BEAST_ESCALATE`) is **opt-in and pending its own A/B**: the wiring touches two era-hashed files and is a held draft PR (#90), not in `main`
- **`language_reference`** (the pull surface, see Tool Suite above): MCP/WebUI, admin profile only, never the runner's registry; the `beast-lang` skill (`prompt_index: false`) documents the library for cloud models working in this repo
- **Synthesis** (`scripts/lang-synthesize.sh draft|status|promote`, `agents/lang/synthesize.py`): a model *drafts* candidate claims from the corpus; the real verifier accepts or rejects; survivors land in `claims/staging/` for a human review, and `promote` re-verifies all-or-nothing and rebuilds the escalation index. Staging is never served. `draft` names no default endpoint (`OPENBEAST_LANG_SYNTH_URL` unset is a refusal) and will not run while someone else holds the GPU lease. The harness is built and tested against a stub model; the real run is pending the GPU (§11)

## Remote access & beast-slot (client/server)
- **Tailscale remote access** (`scripts/setup-tailscale.sh`): the whole stack stays loopback-bound; your private tailnet gets HTTPS access to the WebUI (`:443`) and the OpenAI-compatible API (`:8443`) — WireGuard device identity, never the public internet (funnel is deliberately not offered)
- **beast-slot**: the rig remains the full command center AND publishes its intelligence for other devices — `--publish-slot` adds a read-only discovery API (`:8444/api/slot`: the *actually loaded* model, slot busy/total, context, health) so clients know what they're talking to; slot-count-agnostic contract, ready for future multi-slot/fleet serving. See [`BEAST_SLOT.md`](BEAST_SLOT.md)
- **OpenBeast client** (`scripts/setup-client.sh`, macOS + Linux): any device runs OpenCode + the complete 18-tool arsenal locally — files, shell, and spawned agents act on the *client's* disk — while inference streams from the rig; `openbeast-client` CLI (status/agent/search/update/uninstall), optional client-local SearXNG (`--local-search`), optional bearer auth (`--api-key`). Data-flow promise: nothing leaves your tailnet
- **beast-artifact** (opt-in, `BEAST_ARTIFACT=true`) — a URL for anything the model renders: hand any self-contained HTML page to `publish_artifact` or `scripts/artifact.sh` and get back a durable `uuid4` URL on the tailnet (`--publish-artifact` adds `:8446`), private to the publisher by default. Re-publishing the same id keeps the URL and adds an immutable version; a mobile-first gallery and a viewer shell (version picker, theme toggle, copy link) make it openable from a phone. Model-authored HTML is treated as hostile: the page renders in an opaque-origin `sandbox` iframe under the repo's first CSP — no storage, no `fetch`, no downloads, scripts only from the same four CDNs Claude Code allows. Reads are gated on tailnet identity (`ARTIFACT_OPERATORS`, unlisted → 404); **writes are loopback-only in v1**. The link's host is *detected* — `agents/artifact.py` asks `tailscale serve` which name publishes `:8446`, and until you publish it the URL is the loopback one, which the tools say **no browser can open** rather than handing over a dead link (`ARTIFACT_BASE_URL` overrides only if you front the viewer yourself). Supporting files (`--file app.js=dist/app.js`) are framed under a capability path, `/raw/<id>/v/<n>/~<token>/…`, because an opaque-origin document is cross-site even to the server that hosts it; the token is an HMAC keyed by `.run/artifact-raw.key`, not an identity — every read gate still applies. See [`BEAST_ARTIFACT.md`](BEAST_ARTIFACT.md)
- **beast-chat** (opt-in, `BEAST_CHAT=true`, `:8445`): the operator console for the rig's *own* long-running work. What Claude Code's mobile app does for Claude Code sessions, OpenBeast does for its agents and campaigns — from a phone on the tailnet, list every session running on the rig, watch its transcript stream live, **send it a message that lands at its next turn**, stop it, or start a new agent. Put the phone to sleep mid-stream and reattach an hour later: the page reopens the stream with the byte offset it left off at, so there are no duplicate events and no gap. Two session kinds, because the things most worth watching are not all agents: `agent` (a `runner.py` process, steerable) and `job` (`./scripts/job.sh run --title "T1.17 campaign" -- bash …` wraps any command — campaigns, sweeps, quantization runs — giving it its own process group so a stop reaches the grandchildren, both pid and pgid on record, and a terminal state that tells the truth: exit 0 → done, non-zero → failed, SIGTERM → stopped). A session writes its **own** ledger record (`.run/sessions/<id>.json`, 0600), so every spawn path appears without knowing beast-chat exists — and agents now survive a tool-server restart instead of being SIGTERMed by its `atexit` hook. **Steering is locked out of eval runs by three independent locks**, each sufficient on its own and the first of them unconditional (`OPENBEAST_EVAL`, set by `run_eval.py` in every child env; `OPENBEAST_TASK_PATHS`; and explicit `--steer`/`--session-id` argv — there is no environment opt-in): an injected operator message would change one arm of a paired measurement and the resulting leaderboard row would not look corrupted, it would look like a result. Auth is two-tier for a reason — **reading** is your tailnet login against `CHAT_OPERATORS` (404, never 403, for anyone else), **writing** additionally needs an enrolled device key carrying the new `chat` scope (`./scripts/clients.sh enroll phone --scope chat`), because starting an agent is remote code execution and a proxy-injected header is forgeable by anything already on the box. Publish with `setup-tailscale.sh --publish-chat` (`:8445` → `CHAT_PORT`, default 3003); `healthcheck.sh` and `doctor` each carry a row for it (doctor **fails**, not warns, when `:8445` is published and nothing answers). Sessions the console starts run in their **own** memory-capped systemd scope (`OPENBEAST_CHAT_JOB_MEM_PCT` percent of RAM, default 50; `0` disables), outside the stack's unit — so `./stop.sh`, including the one an update asks for, never takes a phone-started job with it, and a runaway job cannot OOM the model. See [`BEAST_CHAT.md`](BEAST_CHAT.md)
- **Keyed mode** (`LLAMA_API_KEY`, off by default): when enabled, the entire stack presents the bearer — WebUI, healthcheck, agents, evals, router, dashboard, clients

## Multi-device / multi-user (beast-gate)
Local inference servers have no concept of a *user*: llama.cpp offers one flat API key, no per-caller accounting, opportunistic slot assignment, and an unbounded queue with no timeout or preemption — and publishing it exposes its entire route table. `agents/edge.py` is the missing hop, and the only place on the inference path where identity exists. Opt-in (`EDGE_GATE=true`), fails closed, and it does not sit in front of your local frontends — enabling it changes what the *tailnet* sees, not what the rig does.
- **Per-device bearer keys**, hot-reloaded from `.run/clients.json` — revoking a lost laptop blocks its next request within seconds, with no llama-server restart (which would destroy the KV cache and every live conversation)
- **Strict path allowlist**: remote callers reach `/health`, `/v1/models`, `/v1/chat/completions`, `/v1/completions`, `/v1/embeddings` and nothing else. `/lora-adapters` (global model mutation), `/slots`, `/props`, `/v1/stream/<id>` (read or cancel another generation) and `/infill` return **404** — not 403, so a caller learns nothing about what exists
- **Tenancy hardening**: client-supplied `id_slot` is stripped (upstream it is unauthenticated, wraps onto another tenant's slot, and jumps the deferred queue) and re-injected only from the server-side device→slot map; `X-Conversation-Id` is namespaced per device; client-asserted identity headers are stripped and re-asserted from the authenticated device
- **Admission control** the model server cannot provide: token bucket (`EDGE_RATE_LIMIT`) plus a concurrent-generation cap (`EDGE_MAX_INFLIGHT`) per device, returning 429 with `Retry-After`
- **Inference audit + metering**: one row per completion in `.run/inference-audit.jsonl` — `request_id` (echoed to the caller as `X-OpenBeast-Request-Id`), `device`, enrollment-stable `device_uid`, `user_claimed`, model, status, duration, prompt/completion tokens. Never content, never key material. Prometheus at `/gate/metrics` (requires a device key or the rig-local token — it exposes per-device usage); rotated by logrotate
- **Device lifecycle** (`scripts/clients.sh`): `enroll` (key printed once; only its sha256 is stored) · `list` · `show` · `scope` · `revoke` / `unrevoke` · `rotate` · `remove`. Optional `--slot N` pins a device to a llama-server slot, `--rate N` overrides its limit, and `--scope <name>` grants a capability *beyond* inference (today: `chat`, for beast-chat writes). Scopes are additive to the version-1 registry — a device enrolled before they existed has no `scopes` field, reads as having none, and keeps working; absence is never a grant

## Model governance
- **Weight-registry enforcement** (`WEIGHT_ENFORCE`): `scripts/weights.registry` pins sha256 + byte size for every shipped GGUF, and `serve.sh` now checks the weight it is about to load — closing the last gap in a supply chain where images are digest-pinned and Python deps are hash-pinned. `warn` (default) logs and starts; `strict` refuses; `off` disables. Size-only per launch — a 20 GB sha256 on every start would cost minutes; `verify-weights.sh --deep` is the hash-level check
- **Strict refusals are not "crashes."** A `strict` rejection exits **3**, and `start.sh` refuses to apply `MODEL_ROLLBACK` to it — rolling back would silently serve a *different* model than you configured, defeating the check entirely. `doctor` reports when `strict` is safe to enable on your rig
- **Eval quality gate** — promotion by evidence: `doctor` resolves the default serve script through `evals/benchmark_all.py`'s registry and warns when that model has no leaderboard row **on this host**, or when the script isn't registered for benchmarking at all. A warning, not a refusal — running an unevaluated model knowingly is legitimate; running one unknowingly is the thing worth catching

## Air-gap readiness
An installed rig already serves with no internet at all; **installing and updating** were what needed the network — exactly four fetches on a first install (llama.cpp source, the Python wheels, the ~20 GB weight, the two container images), and nothing could be *told* there was no route, so each one stalled on a connect timeout and was misdiagnosed as something local. Full walkthrough: [`INSTALL.md`](INSTALL.md) § Offline / air-gapped install.
- **`OFFLINE=true`** (`openbeast.conf`; predicate `ob_offline`): every step that cannot succeed is refused up front with the command that satisfies it, instead of attempted. `bootstrap.sh --preflight` skips the network probe and says what to stage; the build passes `-DLLAMA_USE_PREBUILT_UI=OFF` (that fetch stalled ~11 min); `update.sh` skips pulls, digest bumps and index queries and reports what is on disk (`--force` rebuilds llama.cpp without a pull); the compose pull is not attempted; `doctor` reports whether a *rebuild* would succeed offline (source, lock, a wheelhouse that covers it)
- **Hash-pinned Python closure** (`scripts/pydeps.sh lock|verify|check|wheelhouse|audit|install`): `agents/requirements.txt` pins six direct versions and says nothing about the other ~37 packages or their *content*; `agents/requirements.lock` pins the whole closure by sha256 and `bootstrap.sh` and CI install it with `pip --require-hashes`. bootstrap **never falls back on a hash mismatch** (the one event the lock exists to catch — it refuses rather than reinstall the same names unverified from the same index); a lock that is merely *stale* against `requirements.txt` is not installed from (that would put the old versions on the box) and takes a loud fallback to `requirements.txt`, fatal under `OPENBEAST_PIP_STRICT=1`. `update.sh --python` regenerates the lock with the pins; CI's `pydeps.sh verify` goes red on a commit that moves one without the other
- **The wheelhouse**: `pydeps.sh wheelhouse <dir>` on a connected box fills a directory with the exact artifacts the lock names; `pydeps.sh install --from <dir>` on the closed box installs them with no index contacted, verified against the lock at both ends (`audit` checks every file in the dir is in the lock). bootstrap looks in `./wheels`, `./wheelhouse` and `$OPENBEAST_WHEELHOUSE`
- **The signed offline bundle** (`scripts/bundle.sh build|show|verify|sign|install`): `build <dir> [--with-weights[=A,B]] [--no-images]` records llama.cpp source (a `git archive` with the commit recorded), the wheelhouse, the container images and optionally weights, each with its sha256 in `MANIFEST.json`; `verify` re-hashes everything it claims and `install` refuses on a mismatch. **Hashes prove integrity; a signature proves authenticity** — anyone who can write to the stick can rebuild the manifest around their own payload and every hash still verifies, so `sign --key <ssh-private-key>` (ssh-keygen -Y, namespace `openbeast-bundle`, no key material in the repo) and `verify --key <allowed-signers>` exist; an unsigned bundle is not refused but is *said* to be unsigned. Wheels and weights have a second, repo-side line of defence (the lock and `weights.registry` are not in the bundle); images and source have only the signature, which is why it exists. Images: `docker save/load` drops the registry digest compose pins, so install rewrites the compose reference to the loaded image's content ID (the original file is kept)
- **`scripts/fetch-weight.sh <file> | --list`**: fetch any single registry weight by name on a connected box, staged inside the weights dir and size + sha256-verified before an atomic rename; a bad download is deleted, never left to be found later

## beast-campaign (measurement you can trust)
Two small tools that exist because their absence cost real GPU-hours ([`BEAST_CAMPAIGN_PLAN.md`](BEAST_CAMPAIGN_PLAN.md)).
- **`scripts/gpu-lease.sh run <label> -- <cmd>` | `acquire` | `release` | `status`**: an *advisory* exclusive lease on the card (`.run/gpu.lease`), identity = **pid + start time**, never pid alone (the kernel recycles pids). It cannot stop a process that does not ask; what it does is give everything that *does* ask a truthful answer — which is all the 2026-09-14 contamination needed (six build agents ran inside a measurement's window; nothing existed for them to consult). Consulted by `healthcheck.sh --restart` (a held lease means the stack's model is not relaunched into a campaign's window), by `stop.sh` (a held lease leaves llama-server processes alone — stop the job first), and by `lang-synthesize.sh draft`
- **`scripts/eval-era.sh` | `--files` | `--check <hash>`**: prints the eval cache era — the hash of the six files that define what an eval unit sees (`system-prompt.md`, `system-prompt-tools.md`, `opencode.json`, `agents/runner.py`, `agents/tools.py`, `evals/SUITE_VERSION`) — and `--check` turns "rows either side of a change are not comparable" from something people remembered into a precondition a campaign asserts at start and between stages, with an exit code
- **The watchdog and `stop.sh` signal by identity**: `scripts/lib/proc.sh` (`ob_pid_matches`) requires a recorded pid to be alive *and* still running the expected command before it is signalled — a pidfile that survived a reboot never SIGTERMs a stranger — and `healthcheck.sh` treats a llama-server whose `/health` says `Loading model` as **LOAD**, not down (bounded by `OPENBEAST_LLAMA_LOAD_GRACE`, default 900 s), because killing a loading model *is* the outage

## Operations
- **Drive wear tracking** (`scripts/ssd-wear.sh`, plus a `doctor` row): agent workloads write hard — model loads, eval-cache and KV churn, log growth, swap storms — and NAND dies by writes. Reads SMART **read-only**, resolves the drives actually backing your weights and repo mounts (through `lsblk --inverse`, so LUKS/LVM layouts work), and reports GB-written/day plus projected days to 100% wear from a bounded history in `.run/ssd-wear.json`. Advisory by design: always exits 0, and **warns rather than staying silent** when it can't read — a green row for health nobody measured is the worst outcome such a tool can produce. `--json` for machines, `--snapshot` to record a datapoint
- Daemon mode: `./start.sh -d` returns when the model is loaded and keeps the stack running in a **memory-capped scope** (a runaway process can never take down the box); `./start.sh --status` shows what's up, and `./stop.sh` shuts everything down gracefully any time
- Health monitor with auto-restart (`scripts/healthcheck.sh`)
- **`./start.sh doctor`** — one-shot diagnosis of a configured/running stack: GPU floor + VRAM headroom, disk, file modes and secret hygiene, pinned dependency drift, digest-pinned images, and per-service health, each with a fix hint (exit 1 on any failure). Where `bootstrap --preflight` checks "can I install here", doctor checks "is what I installed healthy and secure"
- **Extension system** (`scripts/ext.sh`): hot-pluggable optional services (compose fragments or background processes) that attach without editing core files — ships with a read-only status dashboard. See [`extensions/README.md`](../extensions/README.md).
- End-to-end smoke test (`tests/test_smoke.sh`)
- **291-unit eval suite** (137 base tasks, 31 with multi-language variants across 6 languages; hardened v4) with automated validation; full distribution in [`evals/README.md`](../evals/README.md)
- **Multi-model benchmark** runner (`evals/benchmark_all.py`) that sweeps every model and produces a **capability-ranked** leaderboard (scoring v2: problem-solving + language breadth)
- Per-task tracking of accuracy, speed, prompt/completion tokens, and API-equivalent cost (`evals/scoring.py`)
- Multi-language variant support: a single task can have Python / Go / C / C++ / Rust / Zig versions (6 languages), scored fractionally
- Test suite covering scripts, tools, MCP server, and eval tasks (`tests/run_tests.sh`)
