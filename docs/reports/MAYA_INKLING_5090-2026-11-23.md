## 1. Summary

- **Status: evaluated, not adopted (2026-11-24 01:56).** Speed and
  correctness measurement only, no eval arm, no board row. Basalt stays the
  Inkling engine.
- **What it is.** Project Maya (`mw00/project-maya`, MIT) is a C++/CUDA
  inference project for big MoE models. Its code began as Strata's
  ([§4](#4-relation-to-strata-and-basalt-verified)), as Basalt's did, but
  `maya-ik2` is its own Inkling 2 engine, released as an "experimental
  preview" in v1.1.72 (2026-11-21). It drafts with DSpark, has an
  OpenAI- and Anthropic-compatible server, returns `reasoning_content`, and
  keeps Inkling's thinking on.
- **Our existing Maya adapter is the same repo, a different version and job.**
  It pins v1.1.65 (`c81fab6c`) for GLM big mode and has never run. That
  version predates Inkling support, so the adapter cannot serve Inkling
  ([§5](#5-our-existing-maya-integration-and-why-it-cannot-serve-inkling)).
- **Weights ([§6](#6-which-of-our-inkling-weights-it-can-use)).** It reads only
  `inkling2`-keyed GGUFs with NVFP4 or Q8_0 experts. Of our files, that is
  **exactly one model file**: unsloth's `Old_Support/…UD-Q4_K_XL`
  (`e62d463c…`, Maya's own pin). Two drafters also load: the Old_Support DSpark
  Q8_0 GGUF and Blackfrost's `mtp.safetensors`, which is byte-identical to
  thinkingmachines'. It cannot read the current unsloth files
  (`inkling2_loop`), orcarouter's, the Derisked safetensors, or the Basalt and
  Strata packs. **The Derisked eval model cannot run on it.**
- **Security ([§7](#7-security-and-supply-chain-review-read-only-before-anything-ran)).**
  No malware, telemetry or engine network code. The server has default-on
  network features (a GitHub update check plus self-update, model
  download/delete, and image-URL or local-file fetching for any client when
  vision is configured). We switched those off, built from source with
  `--network none`, and ran it in the hardened sandbox. **The DNS gap is
  closed:** `--dns 127.0.0.1` on the no-NAT bridge makes `example.com` FAIL
  ([§9.1](#91-the-dns-fix)).
- **Measured ([§10](#10-results-against-basalt)), same probes as Basalt, stock
  model, 5090.** These are not "similar numbers to Basalt":

  | | Maya v1.1.76 | Basalt v0.5.7 (stock pack) |
  |---|---:|---:|
  | Single stream, thinking off, code / prose | **329 / 204** | 376 / 307 |
  | Single stream, thinking high, code / prose | **333 / 235** | 417 / 309 |
  | Plain decode, no drafter | 210 / 210 | — |
  | 4 streams, aggregate | **350 / 354** (drafting forced off, ctx 64K) | 702 / 624 |
  | Prefill 4K / 16K / 32K | **5.9K / 6.1K / 6.0K** | 18.1K / 19.3K / 17.6K |
  | KLD vs UD-Q8_K_XL, top-1 | **0.0137, 94.81%** (FP8 KV) | 0.0128, 94.93% |

  Single stream, Maya reaches 87% of Basalt on code and 66% on prose. It
  manages half Basalt's 4-stream aggregate and a third of its prefill. One
  code prompt reaches 513 tok/s. Correctness matches Basalt and beats
  llama.cpp on the same file (KLD 0.0162). Drafting does not change greedy
  output (byte-identical on all six prompts). Conformance passes at c=1 and
  c=4, the 16K needle passes, and thinking plus tool calls work, streamed and
  not.
- **Verdict ([§11](#11-verdict)).** Not adopted. It is slower than Basalt on
  every axis that matters here, cannot load the Derisked model the eval uses,
  and is an untested preview on Blackwell upstream. Revisit only on the
  conditions listed in §11.

### 3.1 Inkling 2 Mini in Maya: `maya-ik2`

- **Status: "an experimental preview".** Added in v1.1.72 (2026-11-21, `cce2de0e`;
  `src/ik2` is absent at v1.1.71), credited to `alesha-pro` with
  `mrsirg97-rgb`, `OscarSheng` and `cobra91` (`CHANGELOG.md` v1.1.72 credits).
  `docs/INKLING2.md:445-446`: "tested on RTX 3090s (sm_86) and V100s (sm_70);
  Turing (sm_75) kernel-tested only, **Blackwell (sm_100 / sm_120)
  compile-checked only**". The 5090 is sm_120.
- **Design** (`docs/INKLING2.md` §8, claim unless re-measured here): every
  expert resident in VRAM on a 24 GB+ card, the token path as one CUDA graph
  (757 launches a token), NVFP4 experts on the tensor cores straight from
  their blocks, FP8 or FP16 KV, up to 262,144 tokens with every expert
  resident (1M with experts offloaded).
- **Speculative decoding: DSpark**, the model's own drafter
  (`--draft mtp.safetensors` or unsloth's `dspark-…-Q8_0.gguf`, `src/ik2/ik2_draft.cu`),
  plus prompt lookup (`src/spec/suffix_drafter`), chosen per step by a
  controller. **Claim:** greedy output is bit-identical with drafting on and
  off (the "exact window", `docs/INKLING2.md` §8 "Drafting on = drafting off").
  No MTP head beyond DSpark.
- **Server side** (`docs/INKLING2.md` §6 "Serving"): thinkingmachines' own chat
  template (`tools/ik2/chat_template.jinja`); thinking levels by
  `reasoning_effort` (`none` … `max`, default `high` 0.9) — **thinking is not
  forced off**, unlike Strata; the model's typed segments are rewritten into
  `reasoning_content` and OpenAI tool calls (`serve/frontend.py:1365`,
  `class InklingRewriter`); `tool_choice` for a named tool is forced, `"required"`
  is not (open issue #1171 item 2, #1160). Chat templates render in Jinja's
  `ImmutableSandboxedEnvironment` (`serve/frontend.py:30,47`).
- **Open Inkling issues read** (`gh issue view N --repo mw00/project-maya`):
  #1171 (four findings on a 3090: IQ3_XXS / IQ4_XS expert tensors refused for
  Mini, `tool_choice: required` not forced, …), #1173 (mixed-format dense
  weights switch the resident path off), #1196 (`--parallel`: CUDA-graph OOM
  when the running slots change; the engine sometimes hangs), #1136 / #1107
  (two-GPU bugs), #1129 ("minimal" effort reaches the template as 0.1).

Nothing in Maya's README, `docs/` or `CHANGELOG.md` measures Inkling on a 5090
(`git grep -n -i -E '5090|sm_?120|blackwell' -- docs/INKLING2.md docs/MODELS.md CHANGELOG.md README.md bench/results`:
the only 5090 hit is the reference check run in fp32 on one, §3.1 of their doc).

|---|---|---|---|---|
| `docs/INKLING2.md` §8 table | RTX 3090, UD-Q4_K_XL, FP8 KV | yes | 47 / 4,096 tokens deep | 110-125 tok/s plain decode; prompt 2,504 tok/s at 4K |
| `docs/INKLING2.md` §8 "A step's time" | RTX 3090 (300 W), DSpark Q8_0, greedy | yes | new code / tool call / edit / prose | 201 / 201 / 210 / 135 tok/s with drafting, 124 without; "through the server new code 207" |
| `CHANGELOG.md` v1.1.76 | RTX 3090 | yes | new code | "from 140 to about 200 tok/s" |
| Issue #1170 (`Thymos2027`) | RTX 5060 Ti 16 GB, Windows, offload path | yes | `maya --bench` (256-token answers) | Q4_K_XL 46.0 tok/s, prefill ~1,170-1,200 |
| Issue #1159 | 2x RTX 5060 Ti (sm_120), Windows | yes | CLI | 54-56 tok/s |
| **Issue #1115 (`CDC6600`)** | **one RTX 5090**, a Blackfrost-Derisked checkpoint converted to GGUF with an **unmerged** converter, `--draft mtp.safetensors` | not stated | not stated | **"233-301 tok/s decode"** |

That last line is the only 5090 Inkling figure found for Maya. It is a third
party's, on a file Maya cannot produce at the pin, with the text and stream
count unstated. It is **below** Basalt's single-stream code numbers (376-417)
and in the range of its prose numbers (307-356). "Similar numbers to Basalt"
is therefore **unsupported by any published source**; part 2 measures it.

**Bandwidth arithmetic.** The Strata report's §8 counts ~4.14 GB read a token
from this file (GGUF tensor sizes); Maya's own figure is "3.7 GB: half the
experts', half the dense" (`docs/INKLING2.md` §8). At the 5090's 1,792 GB/s
plain single-stream decode is capped at **433-484 tok/s**; anything above
needs accepted drafts. Maya's 3090 numbers sit at 124.8 / (936 / 3.7) = 49%
of that card's cap. Scaled to the 5090's bandwidth at the same efficiency
(an **estimate**, not a measurement: launch overhead does not scale with
bandwidth): ~240 tok/s plain, ~390 on new code and ~260 on prose with
drafting (the 3090's 201/124 and 135/124 ratios). The 233-301 claim is
within physics without any speculative help.

## 6. Which of our Inkling weights it can use

**What `maya-ik2` reads, at `8c618a59`** (verified in code):

- A GGUF whose keys are under **`inkling2.`**: `const std::string a =
  "inkling2.";` and every hyper-parameter read as `S.get(a + k)`, dying with
  "no key inkling2.…" otherwise (`src/ik2/ik2_main.cu:5978-5986`). No code
  path mentions `inkling2_loop` (`git grep inkling2_loop -- src` empty). Maya's
  own manifest says it: "general.architecture inkling2 … which maya-ik2
  reads; the files in Mainline_Support/ (inkling2_loop, llama.cpp master's)
  are not offered" (`tools/ik2/download.json:2`).
- Expert tensors only of a type with a block decoder, and only if **both C
  and F are whole blocks**: `block_values` is non-zero for NVFP4 (64), Q8_0
  (32), Q5_K, Q6_K, IQ3_XXS, IQ4_XS (256) (`src/ik2/ik2_kernels.cu:7594-7597`),
  checked by `if (C % bv || c.F % bv) die("a row is not whole … blocks")`
  (`src/ik2/ik2_main.cu:6624-6626`). Mini's F is 1,152 = 4.5 x 256, so on Mini
  **only NVFP4 and Q8_0 experts load**; BF16, IQ1/IQ2, IQ3_S, IQ4_NL, Q3_K,
  Q4_K, Q5_0/1, MXFP4 do not (open issue #1171 proposes the per-row check).
- An NVFP4 expert tensor must have its `.scale` (`ik2_main.cu:6630`).
- Dense tensors: F32, BF16 or a block type above (`host_f32`,
  `ik2_main.cu:665-678`; matrices `ik2_main.cu:471-474`); the resident token
  path needs planar Q8_0 (`ik2_main.cu:3451`, issue #1173).
- The drafter: a safetensors `mtp.safetensors` or a GGUF of architecture
  `dflash` that has `dspark_hidden_out.weight` and `dflash.target_layers =
  [5,23,41,48]` (`src/ik2/ik2_draft.cu:297-325`).

## 7. Security and supply-chain review (read only, before anything ran)

### 7.1 Verdict

- **Genuine MIT open source; no malware, obfuscation, credential access or
  phone-home in the engine.** OK to build from source at the reviewed pin
  and run in the hardened sandbox, with the server's network features off.
- **Unlike Basalt, the server has default-on network features**: a GitHub
  release check (dashboard-triggered), a self-update that fast-forwards the
  checkout and restarts, model downloads and deletes (`/api/pull`,
  `/api/delete`), and image fetching from any URL or local path for *any*
  client when an image encoder is configured. All are switchable or
  unconfigured in our run (§7.4) and the sandbox blocks the rest.
- **Python dependencies are unpinned** (`setup.py:32`), so we use none of

### 7.2 Supply chain (verified)

- **Checked-in binaries.** `git ls-files -z | xargs -0 file --mime-type`
  over 1,814 files: no ELF, PE, Mach-O or shared object. The non-text files
  are images, F32/GGUF test fixtures and expert-profile tables under `data/`
  (ten `.f32` dumps are typed "DOS executable (COM)" by `file`'s magic; they
  are raw floats), and **nine vendored wheels** in `third_party/wheels/`
  (rich, textual, pygments, … for the setup screen). Each wheel's sha256
  equals PyPI's for that file (`curl https://pypi.org/pypi/<pkg>/<ver>/json`;
  9 of 9 MATCH). No submodules, no Git LFS.
- **Build-time downloads.** One: if `MAYA_GGML_DIR` is unset, CMake
  `FetchContent`s llama.cpp from GitHub at a pinned commit, `GIT_TAG
  3cf03257f219afbe7334045ff7c6a06ac68c627d` (`CMakeLists.txt:1667-1676`); it
  builds ggml's CPU backend and patches a copy of its MMQ sources with
  `third_party/ggml/mmq-fused-swiglu.patch` (`CMakeLists.txt:1795-1835`).
  We pass `MAYA_GGML_DIR` (the same commit, from a local llama.cpp clone)
  and build with `--network none`.
- **Installers.** `setup.sh` / `maya.py --setup` download llama.cpp as a
  commit zip (`setup.py:29-30`), `pip install` unpinned `PY_PACKAGES`
  (`setup.py:32`: numpy, jinja2, regex, pyyaml, tqdm, requests, cmake, ninja,
  pillow, psutil, jsonschema>=4.18,<5), and the model files from Hugging Face
  pinned by revision, size and sha256 (`tools/ik2/download.json`). No `curl
  | sh`; `sudo` appears only in printed hints (`maya.py:1451…`). We use none of
  it. `docker/Dockerfile` uses an unpinned `nvidia/cuda:13.0.0` base and curls
  the llama.cpp zip; not used.
- **CI.** `.github/workflows/{tests,macos,badges}.yml`, actions by tag
  (`actions/checkout@v4`), not by SHA. Releases carry no assets, so there is
  no binary to trust or distrust.
- **Telemetry.** `serve/telemetry.py` is local hardware readings (NVML via
  ctypes in a child process, psutil, sysfs) for the Monitor; no network.

### 7.3 Network code, complete for what we run

- **Engine (`maya-ik2`, C++/CUDA):** none. No `sys/socket`, `netdb`,
  `winsock`, `winhttp` or `curl` include under `src/` or `include/`
  (`git grep -nE '#include\s*<(sys/socket|netdb|arpa/inet|netinet/|winsock|winhttp|curl/)' -- src include`:
  empty). "Remote experts" (`src/core/remote_experts.cpp`) is a second GPU,
  not a network peer. The engine writes one file outside its tree,
  `~/.maya/ik2-offload-calib.txt` (`ik2_main.cu:3198-3202`; `HOME=/tmp` in the
  sandbox), and `--drafting auto` keeps `data/ik2-drafting.txt` in the tree
  (`serve/server.py:2430`).
- **Server (`serve/`):**
  - `serve/update.py:86-90`: GET `https://api.github.com/repos/<origin>/releases/latest`
    when the dashboard asks, at most every 6 h; **`MAYA_UPDATE_CHECK=0` turns it off**
    (`update.py:75`). POST `/api/update` then runs `git` to fast-forward the
    checkout to that tag and restarts (`update.py` docstring, `server.py:7026-7036`);
    it is refused only for a foreign `Origin` or a non-JSON body
    (`_own_page`, `server.py:6946-6957`), so **any API-key holder can trigger
    it**. Read-only tree and no network make it fail in our sandbox.
  - `serve/model_pull.py` (`/api/pull`, the Models page): downloads models;
    `/api/delete` deletes model files. "Model management" is **on by default**
    (`server.py:768-777`); without a key only loopback may use it, with a key
    any key holder (`server.py:6100-6114`). **`MAYA_MODEL_MANAGEMENT=0`** and
    `"model_management": false` turn it off.
  - `Vision.load` (`server.py:2116-2124`) fetches any `http(s)` URL or reads
    any local path named in a request's image, **with no loopback check**
    (Basalt restricts this to loopback clients). It runs only when the run
    config has a `"vision"` encoder; for Inkling without one the server
    refuses pictures in plain words (`server.py:4131-4136`). We configure none.
  - `serve/mcp.py`: starts MCP servers listed in the run config only (`Popen`
    at line 103). None configured.
  - `serve/pdf.py` / attachments: local conversion, `ffprobe` with
    `-protocol_whitelist file` (`server.py:2198`).
- **Credentials, privileges.** No `.ssh`, `HF_TOKEN`, keyring or `setuid`
  in `src/` or `serve/`. The API key comes from `--api-key` or `MAYA_API_KEY`
  (`server.py:7769`) and is compared with `hmac.compare_digest`
  (`server.py:6413-6421`). Every POST is checked first (`do_POST`,
  `server.py:6774`). Without a key the server is open; it warns when bound
  beyond loopback (`server.py:8062-8072`).
- **No `eval` / `exec` / `pickle` / `marshal`** in `serve/*.py`,
  `tools/strata_tokenizer.py`, `setup.py` or `maya.py` outside tests.

### 9.1 The DNS fix

`scripts/dns-probe.sh` runs a throwaway container of our image with the
same hardening, then tries `getaddrinfo` (example.com, huggingface.co,
github.com), TCP out (1.1.1.1:443, 8.8.8.8:53, the LAN router) and a raw
UDP/53 query to 1.1.1.1 (`results/dns-probe.txt`, 01:39):

| Setting | DNS | TCP / UDP out |
|---|---|---|
| A: `--network strata-bench-net` (Basalt's and Strata's setting) | **RESOLVED** all three (example.com → 172.66.147.243) | timeout |
| **B: A + `--dns 127.0.0.1` (used for Maya's server)** | **FAIL** `gaierror [Errno -3]` all three | timeout |
| C: `--network none` (build, KLD) | FAIL | `OSError` (no route) |

With B, Docker's embedded resolver forwards to `127.0.0.1` inside the
container's own namespace, where nothing listens, so names do not resolve.
The published `127.0.0.1` port works unchanged. **This is the fix the Strata
report §15.4 gap 1 asked for.** It works on this Docker (29.9.2) and is
proved by the probe. Basalt's `basalt-serve.sh` can take the same flag at its
next start.

## 11. Verdict

**Not adopted.** Basalt stays the Inkling engine for the 5090.

1. **Slower where it counts.** Single stream, Maya reaches 87% of Basalt on
   code (329 vs 376) and 66% on prose (204 vs 307). Its four-stream aggregate
   is half (350 vs 702) and its prefill a third (6K vs 18-19K). The rumour
   "similar numbers to Basalt" holds only for single code prompts: one reaches
   513, and the only public 5090 figure (#1115, 233-301) is in this range.
2. **It cannot run the eval's model.** `I_T2` runs the Blackfrost Derisked
   weights; Maya reads only the stock unsloth Old_Support Q4_K_XL GGUF of the
   files we have (§6).
3. **Preview maturity.** Blackwell is "compile-checked only" upstream (it
   worked here), `--parallel` turns drafting off and has open graph-OOM and
   hang reports (#1196), and releases come daily.

**What it does well:** the most accurate engine we measured on the 4-bit
file (KLD 0.0137 at FP8 KV, 0.0127 at FP16, against llama.cpp's 0.0162 on
the same tensors), byte-identical greedy output with drafting, a 210 tok/s
plain decode, full harness conformance, and thinking that is not forced off.

**Revisit if** (a) a reviewed release reads `inkling2_loop` GGUFs or the
Derisked checkpoint, (b) prose drafting stops running below plain decode
(a controller fix) and `--parallel` keeps drafting, and (c) its prefill
moves off ~6K. Before any adoption: a reviewed commit, the server's network
features off as in §9, and the `--dns 127.0.0.1` sandbox.
