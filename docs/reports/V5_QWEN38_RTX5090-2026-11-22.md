## 7. Caveats

- **Single seed**, one run. This holds for Q_T2, L1 and L2 as well: small n
  (6 and 39 units), every contrast within churn, and the L1/L2 units ran
  once each, so a 2-unit swing is within what a rerun can produce.
- **Harness host: calibrated afterwards (2026-11-23).** Linux container
  against the Mac; the sandbox differs too (the network gap above). L0, L1
  and L2 share the host, so their contrasts are like for like; their
  comparison with GLM's L1/L2 on the Spark pair is not. The later
  calibration ([report](V5_EVAL_HOST_CALIBRATION-2026-11-23.md)), run on
  harness9 with DeepSeek and carried to these harness10 arms by
  inference, detected no host effect beyond run-to-run variation, from one
  calibration arm. It found two known host effects. One is a Linux-only
  validator bug: `122_gemm_blocked` rejects a binary that imports `dlsym`,
  and Rust's std on Linux/glibc imports it for any thread. The other is
  the agent shell's missing network deny (the 3 exclusions). Both L2 files
  record `122_gemm_blocked_d` as `the binary imports dlsym`: the validator
  stopped at the binary check, so the solution's correctness was not
  measured. The unit counts as a fail only in L2's raw Rust 5/8; the
  L0 → L2 Rust contrast drops it, because L0's row is `server_error`
  (L0 did not reach that check).
- **The lost units are counted as fails** (4 in L0, 3 in Q_T2). Each row
  understates the model by up to that many units until the runner treats
  a truncated tool call as a model turn.
- **Q_T2 against L0 is not a clean pair** (§6): harness9 against
  harness10, and the whole T2 bundle at once. Its +11 is a measured
  difference between two configurations, not an effect of one switch.
- **The scan's window needs the container's zone.** The container writes
  naive UTC timestamps, so scanning a copied result file needs its mtime
  kept (`scp -p`) and `TZ=UTC`; otherwise only part of the run is
  attributed (noted in the sealed review).
