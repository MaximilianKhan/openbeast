## 1. Executive summary

- **The RTX 5090 default passed 39/71 scored (40 raw), SCORE 63.3, on the
  bare harness.** It is the first v5 row for the model OpenBeast ships on a
  single RTX 5090: Qwen3.8 27B Uncensored (abliterated), Q5_K_M GGUF, with
  its MTP head, on llama.cpp. It is #4 on the v5 board by SCORE, behind
  DeepSeek-V4.1-Flash (Mia EXL3) T2 (94.9), Hy4-flash (NVFP4) H_T2 (83.4)
  and GLM-5.3-Flash C (76.7). Those three are the Spark pair's best
  configurations with campaign assists; this row is the bare L0.
- **4 units were lost to infrastructure and count as fails**
  (122_gemm_blocked_c, 122_gemm_blocked_d, 124_rkf45, 173_taskgroup_cancel).
  In each one the model's tool call was cut off, llama-server answered
  HTTP 500 "Failed to parse tool call arguments as JSON", and the runner
  re-sent the identical request until the unit was recorded `server_error`
  (8 to 23 retries). The server was healthy; the fault was the model's
  output, and the runner treats it as an API error. The next-era fix is in
  [HARNESS_NOTES.md](../HARNESS_NOTES.md#next-era-proposals-from-the-2026-11-22-runs-infra-not-model-behaviour), proposal (a).
- **Integrity: 3 units excluded, one of them a pass.** On Linux the agent's
  shell has no network deny (a documented residual gap), and in three units
  the scan flagged off-host access from the agent's shell after the refused
  `fetch` tool. The scan counts that as contamination, so those units
  count as not passed: 40 raw, 39 scored. The review notes are sealed in
  `evals/audit/reviews/`.
- **A different harness host, not calibrated.** The run was driven from
  the rig's eval-host container (Linux), not the Mac harness host that
  drove every Spark row. The cross-host calibration is not done yet; read
  this row beside the Spark rows with that caveat.
- **Zig 0/6.** Python 19/32, Go 4/8, C 6/8, C++ 5/8, Rust 4/8, Shell 1/1.
- **Profile diagnostics (§5, not board rows).** L1 (packs): zig 0 → 4 of
  6. L2 (packs + diagnostics + escalation): zig 4 → 2 against L1; over 36
  compiled units L0 → L2 went 19 → 23 (+4, p 0.29). All within churn,
  single seed. Integrity scan of both arms: 0 contaminated.

## 6. Caveats

- **Single seed**, one run. This holds for L1 and L2 as well: small n
  (6 and 39 units), every contrast within churn, and the L1/L2 units ran
  once each, so a 2-unit swing is within what a rerun can produce.
- **Harness host not calibrated.** Linux container against the Mac; the
  sandbox differs too (the network gap above). L0, L1 and L2 share the
  host, so their contrasts are like for like; their comparison with GLM's
  L1/L2 on the Spark pair is not.
- **The 4 lost units are counted as fails.** The figure understates the
  model by up to 4 units until the runner treats a truncated tool call as
  a model turn.
- **The scan's window needs the container's zone.** The container writes
  naive UTC timestamps, so scanning a copied result file needs its mtime
  kept (`scp -p`) and `TZ=UTC`; otherwise only part of the run is
  attributed (noted in the sealed review).
